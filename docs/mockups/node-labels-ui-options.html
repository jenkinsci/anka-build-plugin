One column of compact rows. Key facts always visible; expand a row (or “Edit”) for the full form in a wide 2-column layout. Best for scanning many labels.

C — Accordion + essentials grid

One label open at a time. Common fields in a compact 4-column grid; everything else under “Show more”. Closest to today’s form model, but much shorter.

What improves in all options

  • Scan labels without scrolling through every field
  • Wider edit area (no 25%-width columns)
  • Rare settings tucked behind progressive disclosure

Trade-offs to keep in mind

  • Jenkins f:repeatable limits how “table-like” we can go without JS
  • Option B may need the most custom UI work
  • Collapsed state needs a clear header (label + template/tag)

My lean: A for most admins; C if you want minimal behavior change. Click a card, then reply here with your pick (or a mix).
